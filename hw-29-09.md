## 1. Процессы и потоки

### 1.1. Функции ОС по управлению процессами и потоками
1. **Планирование процессов** — распределение процессорного времени между одновременно выполняющимися процессами.
2. **Создание и уничтожение процессов.**
3. **Наделение процессов системными ресурсами.**
4. **Реализация обмена данными между процессами.**
5. **Синхронизация процессов и потоков.**

### 1.2. Определения
- **Процесс** — программа, находящаяся в стадии выполнения.
- **Поток** — средство распараллеливания вычислений в рамках одного процесса.
- Процесс рассматривается как заявка на потребление всех видов ресурсов, **кроме процессорного времени**.
- Процессорное время выделяется **потокам**. В простейшем случае процесс состоит из одного потока.

### 1.3. Ресурсы, совместно используемые потоками процесса
- Адресное пространство
- Глобальные переменные
- Открытые файлы
- Дочерние процессы
- Необработанные аварийные сигналы
- Сигналы и их обработчики
- Информация об использовании ресурсов

### 1.4. Преимущества потоков перед процессами
- Создание потоков требует меньших накладных расходов от ОС.
- Быстрота создания потока по сравнению с процессом.
- Потоки одного процесса могут взаимодействовать, не обращаясь к ОС, используя общую память.
- Повышение производительности программы.

### 1.5. Задания, процессы, потоки и волокна
| Название | Описание | Примечания |
|----------|----------|------------|
| **Задание** | Коллекция процессов с общими квотами и лимитами | Используется редко |
| **Процесс** | Контейнер для ресурсов | |
| **Поток** | Единица планирования для ядра | |
| **Волокно** | «Легкий» поток, управляемый полностью в пространстве пользователя | Используется редко |

### 1.6. Состояния потоков
- **Выполнение** — активное состояние, поток обладает всеми необходимыми ресурсами и непосредственно выполняется процессором.
- **Готовность** — пассивное состояние, поток заблокирован в связи с внешними обстоятельствами.
- **Ожидание** — пассивное состояние, поток заблокирован по своим внутренним причинам.

**Переходы между состояниями:**
1. Поток выбран на выполнение.
2. Поток ожидает завершения ввода/вывода.
3. Ввод/вывод завершен (событие произошло).
4. Поток вытеснен планировщиком.

### 1.7. Создание процессов
**События, приводящие к созданию процессов:**
- Загрузка системы.
- Работающий процесс подает системный вызов на создание процесса.
- Запрос пользователя на создание процесса.

**Создать процесс означает:**
1. Создать описатель процесса.
2. Загрузить коды и данные исполняемой программы процесса с диска в оперативную память.
3. В многопоточной системе для каждого создаваемого процесса создать как минимум один поток выполнения.

### 1.8. Идентификаторы, дескрипторы и контекст
- **Дескриптор процесса** содержит информацию, необходимую ядру в течение всего жизненного цикла процесса (состояние, расположение образа в памяти и на диске, приоритеты, идентификатор пользователя, родственные процессы и др.).
- **Контекст процесса** содержит менее оперативную, но более объемную информацию, необходимую для возобновления выполнения с прерванного места: содержимое регистров процессора, коды ошибок системных вызовов, таблица открытых файлов, информация о незавершенных операциях ввода/вывода и др.

## 2. Планирование и диспетчеризация потоков

### 2.1. Планирование
- Определение момента времени для смены текущего активного потока.
- Выбор потока для выполнения из очереди готовых.

**Виды планирования:**
- **Динамическое** — решения принимаются во время работы системы на основе анализа текущей ситуации.
- **Статическое** — решения приняты заранее, работа по расписанию.

### 2.2. Диспетчеризация
Реализация найденного в результате планирования решения:
1. Сохранение контекста текущего потока.
2. Загрузка контекста потока, выбранного в результате планирования.
3. Запуск нового потока на выполнение.

### 2.3. Моменты перепланировки
- Время, отведенное активной задаче, закончилось — задача переводится в состояние готовности.
- Активная задача выполнила системный вызов, связанный с запросом на ввод/вывод или доступ к занятому ресурсу — задача переводится в состояние ожидания.
- Активная задача выполнила системный вызов, связанный с освобождением ресурса — ожидающая задача переводится в состояние готовности.
- Завершение периферийным устройством операции ввода/вывода — соответствующая задача переводится в очередь готовых.
- Внутреннее прерывание сигнализирует об ошибке в активной задаче — задача снимается, выполняется перепланирование.

### 2.4. Алгоритмы планирования
- **Невытесняющие** — активный поток выполняется до тех пор, пока он сам по собственной инициативе не отдаст управление ОС.
- **Вытесняющие** — решение о переключении процессора принимается ОС, а не активной задачей.

### 2.5. Квантование
**Квант** — ограниченный непрерывный интервал процессорного времени, который поочередно предоставляется всем существующим в системе потокам.

### 2.6. Приоритеты
**Приоритет** — число, характеризующее степень привилегированности потока при использовании ресурсов ОС.
- **Фиксированные** — назначается ОС при создании потока и не изменяется.
- **Динамические** — может быть изменен по инициативе потока, пользователя или ОС.

**Приоритетное планирование:**
- **С относительными приоритетами** — приоритет учитывается только при выборе потока из очереди готовых.
- **С абсолютными приоритетами** — выполнение активного потока прерывается, если в очереди готовых появляется поток с более высоким приоритетом.

### 2.7. Смешанный алгоритм
Квантование + приоритеты.

### 2.8. Приоритеты в Windows NT
- **16 уровней реального времени** (16–31).
- **15 варьируемых уровней** (1–15).
- **1 системный уровень** (0).

**Классы приоритетов процессов Win32:**
- Real-time, High, Above Normal, Normal, Below Normal, Idle.
- Каждому классу соответствует набор приоритетов потоков (от Time critical до Idle).

### 2.9. Алгоритм планирования Linux
Поддерживаются три класса потоков:
1. Потоки реального времени, обслуживаемые по алгоритму **FIFO**.
2. Потоки реального времени, обслуживаемые в порядке **циклической очереди**.
3. Потоки **разделения времени**.

- Linux различает **140 уровней приоритета**.
- Потоки реального времени: приоритеты **0–99** (0 — самый высокий).
- Обычные потоки: приоритеты **100–139**.
- Каждому уровню приоритета обычных потоков соответствует свое значение длительности кванта времени.
- Значение **nice** определяет статический приоритет потока. По умолчанию 0, меняется от -20 до +19.

### 2.10. Алгоритмы планирования в ОС пакетной обработки
1. **«Первый пришел — первым обслужен» (FIFO)**
   - Достоинства: простота, справедливость.
2. **«Кратчайшая задача — первая»**
   - Минимизирует среднее оборотное время выполнения задачи.
   - **Оборотное время** — время от момента запуска пакета до получения результата задачи.
   - **Недостатки:** требуется превентивная информация о времени выполнения задач; длинный процесс не пустит более новые краткие процессы.
3. **Наименьшее оставшееся время выполнения.**
4. **Трехуровневое планирование** (планировщик процесса, планировщик доступа, планировщик памяти).

### 2.11. Алгоритмы планирования в интерактивных системах
**Критерий эффективности** — удобство работы пользователя.
1. **Циклическое планирование (квантование)**
   - Простота, справедливость.
   - Слишком маленький квант приводит к частому переключению контекста.
   - Слишком большой квант увеличивает время ответа на интерактивный запрос.
2. **Приоритетное планирование.**
3. **Самый короткий процесс — следующий.**
4. **Гарантированное планирование** — каждому пользователю гарантируется 1/n мощности процессора.
5. **Лотерейное планирование** — раздача процессам лотерейных билетов на доступ к ресурсам. Планировщик случайно выбирает билет.
6. **Справедливое планирование** — учитывается владелец процесса, каждому пользователю распределяется доля процессорного времени.

### 2.12. Планирование в системах реального времени
**Критерий эффективности** — способность системы выдерживать заданные интервалы времени между запуском программы и получением результата (реактивность).
- **Жесткие** — несоблюдение временных ограничений приводит к катастрофическим последствиям.
- **Гибкие** — нарушения графика нежелательны, но допустимы.

**Внешние события:**
- **Периодические** — моменты возникновения можно определить заранее.
- **Спорадические** — моменты возникновения заранее неизвестны.

**Задачи:** независимые и взаимосвязанные.

**Необходимое условие существования расписания:**
\[
\mu = \sum \frac{c_i}{p_i} \leq k
\]
где \(c_i\) — время выполнения, \(p_i\) — период, \(k\) — количество процессоров.

### 2.13. Алгоритм Лью — Лейланда
Классический алгоритм для жестких систем реального времени с одним процессором.
**Предположения:**
- Запросы на выполнение всех задач периодические.
- Все задачи независимы.
- Срок выполнения задачи равен ее периоду.
- Максимальное время выполнения каждой задачи известно и постоянно.
- Время переключения контекста можно игнорировать.
- Максимальный суммарный коэффициент загрузки процессора:
\[
\sum \frac{c_i}{p_i} \leq n(2^{1/n} - 1)
\]
где \(n\) — число задач.

**Суть:** задача с самым коротким периодом получает наивысший приоритет.

## 3. Синхронизация процессов и потоков

### 3.1. Межпроцессное взаимодействие
- Согласование действий процессов.
- Передача информации от одного процесса другому.
- Контроль над деятельностью процессов.

Потребность в синхронизации возникает только в **мультипрограммной ОС** и связана с совместным использованием аппаратных и информационных ресурсов.

### 3.2. Гонки (взаимные состязания)
**Состязания (гонки)** — ситуация, когда два или более потока обрабатывают разделяемые данные, и конечный результат зависит от соотношения скоростей потоков.

### 3.3. Критическая секция
**Критическая секция** — часть программы, результат выполнения которой может непредсказуемо меняться, если переменные, относящиеся к этой части, изменяются другими потоками, пока выполнение этой части не завершено.
- Критическая секция всегда определяется по отношению к определенным критическим данным.
- Чтобы исключить эффект гонок, необходимо обеспечить, чтобы в каждый момент времени в критической секции находился только один поток.

### 3.4. Способы защиты критической секции
1. **Запрет прерываний.**
2. **Блокирующие переменные** — неделимая операция «проверка-установка».

### 3.5. Семафоры Дейкстры
**Семафоры** — переменные, принимающие целые неотрицательные значения и используемые для синхронизации.
- **V-операция (Verhogen — увеличить):** \(S = S + 1\).
- **P-операция (Proberen — проверить):** \(S = S - 1\), если возможно; иначе поток переводится в состояние ожидания.

### 3.6. Классические задачи синхронизации
**«Читатели — писатели»:**
- Буферный пул из N буферов.
- \(e\) — число пустых буферов, \(f\) — число заполненных.
- Читатели используют \(P(e)\) и \(V(f)\), писатели — \(P(f)\) и \(V(e)\).

**«Обедающие философы»:**
- Каждый философ может есть, только держа две вилки (справа и слева).
- **Проблемы:** взаимная блокировка, ресурсное голодание.
- **Решения:**
  - **Официант** — философы ждут разрешения официанта перед взятием вилки.
  - **Иерархия ресурсов** — вилки нумеруются, философ всегда берет сначала вилку с меньшим номером.

**«Спящий брадобрей»:**
- Парикмахер спит, пока нет клиентов. Клиент либо будит парикмахера, либо ждет.
- **Решение:** использование мьютекса для изменения состояния.

### 3.7. Взаимные блокировки (тупики, дедлоки)
**Взаимная блокировка** — ситуация, когда несколько процессов борются за ресурсы, и ни один не может завершить работу.

**Условия взаимоблокировки (Коффман, Элфик, Шошани):**
1. **Условие взаимного исключения** — ресурс отдан одному процессу или свободен.
2. **Условие удержания и ожидания** — процесс, удерживающий ресурс, может запрашивать новые.
3. **Условие отсутствия принудительной выгрузки** — у процесса нельзя забрать ранее полученные ресурсы.
4. **Условие циклического ожидания** — существует круговая последовательность процессов, каждый из которых ждет ресурс, занятый следующим.

### 3.8. Моделирование взаимоблокировок
- **Граф ресурсов:** квадраты — ресурсы, круги — процессы.
- **Цикл в графе** — признак взаимоблокировки.

### 3.9. Стратегии при столкновении с взаимными блокировками
- **Пренебрежение проблемой (страусовый алгоритм).**
- **Обнаружение и восстановление.**
- **Динамическое избежание тупиков.**
- **Предотвращение** — опровержение хотя бы одного условия возникновения тупика.

### 3.10. Обнаружение взаимоблокировок
**При одном ресурсе каждого типа:**
- Для каждого узла графа выполняются шаги по поиску цикла.

**При нескольких ресурсах каждого типа:**
- \(m\) — число классов ресурсов, \(n\) — количество процессов.
- \(E\) — вектор существующих ресурсов.
- \(A\) — вектор доступных ресурсов.
- \(C\) — матрица текущего распределения.
- \(R\) — матрица запросов.
- Алгоритм ищет процесс, чьи запросы \(R_i \leq A\). Если найден — ресурсы выделяются, процесс завершается, \(A\) увеличивается.

### 3.11. Когда следует искать тупики
- Когда запрашивается очередной ресурс.
- Периодически, через определенный промежуток времени.
- Когда загрузка процессора слишком мала.

### 3.12. Выход из взаимной блокировки
1. Восстановление при помощи принудительной выгрузки ресурса.
2. Восстановление через откат.
3. Восстановление путем уничтожения процесса.

### 3.13. Динамическое избежание взаимоблокировок
**Траектории ресурсов** — графическое представление запросов и освобождений ресурсов процессами.
- **Опасные и безопасные состояния.**
- **Безопасное состояние** — система не в тупике и существует порядок планирования, при котором каждый процесс может завершиться.
- **Небезопасное состояние** — такой гарантии нет.

### 3.14. Алгоритм банкира
**Для одного вида ресурсов:**
- Проверка запроса на безопасность состояния.
- Если состояние безопасно — ресурс выдается, иначе — отказ.

**Для нескольких видов ресурсов:**
- \(E\) — существующие ресурсы, \(P\) — занятые, \(A\) — доступные.
- Матрицы распределенных ресурсов и необходимых ресурсов.
- Алгоритм ищет процесс, чьи потребности \(\leq A\). Если найден — ресурсы выделяются, процесс завершается, \(A\) увеличивается.

### 3.15. Предотвращение условий взаимоблокировок
- **Взаимное исключение** — организовать подкачку данных.
- **Удержание и ожидание** — запрашивать все ресурсы на начальной стадии.
- **Отсутствие принудительной выгрузки** — отбирать ресурсы.
- **Циклическое ожидание** — пронумеровать ресурсы и упорядочить.

## 4. Средства синхронизации

### 4.1. Системные средства синхронизации
- Системные семафоры.
- Мьютексы.
- События.
- Объекты ядра: таймеры, файлы, процессы, потоки.
- **Wait()/Set():** Windows NT (WaitForSingleObject, SetEvent), UNIX (sleep, wakeup), OS/2 (DosSemWait, DosSemSet).

### 4.2. Мьютексы
**Мьютексы** (от MUTual Exclusion) — объекты ядра, позволяют координировать взаимное исключение доступа к разделяемому ресурсу.

### 4.3. Системные семафоры
Принцип действия мьютексов, но с возможностью подсчета ресурсов, что позволяет заранее определенному числу потоков одновременно войти в синхронизируемый участок кода.

### 4.4. События
Используются в качестве сигналов о завершении какой-либо операции.
- **С ручным сбросом** — все потоки, ожидающие события, переходят в состояние «готовность».
- **С автоматическим сбросом** — в состояние «готовность» переводится только один поток.

### 4.5. Сигналы
**Сигнал** (виртуальное прерывание) — сообщение, которое система посылает процессу или один процесс посылает другому.

### 4.6. Мониторы Хоара
**Монитор** — пассивный набор разделяемых переменных и повторно входимых процедур доступа к ним, которыми процессы пользуются в режиме разделения, причем в каждый момент времени им может пользоваться только один процесс.

### 4.7. Ждущие таймеры
- **Режим «ручного сброса»** — таймер переходит в установленное состояние при истечении задержки и остается до вызова SetWaitableTimer.
- **Режим «автоматического сброса»** — таймер переходит в установленное состояние при истечении задержки и остается до первого успешного вызова функции ожидания.
- **Режим интервального таймера** — перезапускается с заданной задержкой после каждого срабатывания.

## 5. Обмен данными между процессами и потоками

### 5.1. Конвейер (канал, pipe)
**Конвейер** — буфер в оперативной памяти, поддерживающий очередь байт по алгоритму FIFO.

### 5.2. Каналы
- **Безымянные каналы** — позволяют обмениваться данными только родственным процессам.
- **Именованные каналы** — имеют имя (запись в каталоге файловой системы), пригодны для обмена между произвольными процессами.

### 5.3. Очереди сообщений
- Позволяют процессам и потокам обмениваться структурированными сообщениями.
- Являются глобальными средствами коммуникаций, так как каждая очередь имеет уникальное имя.

### 5.4. Почтовые ящики
Обеспечивают только однонаправленные соединения.

### 5.5. Сокеты
Механизм обмена данными между процессами, в том числе по сети.

### 5.6. Разделяемая память
Несколько процессов имеют доступ к одному и тому же участку физической памяти.
- **Преимущество:** высокая скорость обмена.
- **Недостаток:** требуется синхронизация доступа.
